# 领域词汇与六个模块

## 核心词汇

- **项目（Project）**：一部小说的工作空间和权限、配置边界，也是跨聚合操作的关联范围。
- **设定（Canon）**：创作过程中被视为真实且应保持一致的人物、关系、地点、规则与历史事实。
- **叙事计划（Narrative Plan）**：作者希望故事如何推进的意图，包括故事弧、情节点、伏笔和章节目标；它不是已经发生的正文事实。
- **稿件（Manuscript）**：可编辑和发布的章节文档及其内容版本。
- **聚合（Aggregate）**：必须在一次一致性边界内校验并提交的领域对象。聚合只能由自身命令修改。
- **聚合版本（Aggregate Version）**：聚合每次有效状态变更后单调递增的整数，用于乐观并发控制。
- **变更集（Change Set）**：一次用户可感知操作中提交的、可审计的原子变更集合。
- **快照（Snapshot）**：某一聚合版本的完整状态检查点，用于加速恢复，不替代变更历史。
- **领域事件（Domain Event）**：已经成功提交且不可更改的领域事实。
- **智能建议（Intelligence Proposal）**：AI 生成的候选内容或诊断结果；在业务命令接受前不属于领域事实。

## 模块职责

### projects

拥有项目身份、标题、生命周期、功能设置和项目级修订。它建立工作空间边界，但不拥有其他模块的业务内容。

该模块的作品目录垂直切片已经投入使用：`NovelProject`、SQLite 仓储、API v1 与新作品台共同作为新项目元信息的权威路径。其他五个业务模块仍处于后续迁移阶段，旧文件详情继续承载其现有能力。

### canon

拥有人物、人物关系、世界设定和已确认事实。对设定的修改必须在本模块校验引用和唯一性。其他模块只能引用稳定标识，不直接改写设定内部数据。

### narrative

拥有故事弧、情节点、伏笔、章节目标与大纲等创作意图。它可以引用 canon 标识和 manuscript 章节标识，但不拥有正文，也不能把计划自动视为已发生事实。

### manuscript

拥有章节身份、顺序、状态、正文文档和内容版本。保存、生成提交与发布均通过本模块命令；来自 narrative 或 intelligence 的内容先作为输入或候选，再由命令落入稿件。

### changes

拥有变更集、审计索引、撤销与恢复编排。它记录其他模块已经接受的变化或发起受控的反向命令，但不越过目标模块聚合直接写表。

### intelligence

拥有 AI 请求编排、建议、摘要、检索索引和一致性报告。它读取经授权的上下文并产出候选结果，不直接修改 projects、canon、narrative 或 manuscript 聚合。提供商不可用时，核心查看、编辑和保存能力仍可工作。

## 平台能力

- **database**：Node 内置 `node:sqlite`、Drizzle 连接、事务与迁移适配。
- **events**：outbox 持久化、领取、投递和消费者幂等设施。
- **jobs**：可重试后台任务的调度与执行。
- **ai**：模型提供商、流式生成和测试替身所实现的端口。
- **observability**：结构化日志、指标、追踪和关联标识。

平台只实现技术能力，不决定领域规则。模块通过端口描述需要，应用组合根选择具体平台实现。
